BitLang is a tiny language for making little programs and games inside Bitbook notes (and Omicron pages). Add a Programs skill to a note and it becomes a chip, just like a BeepBox song: press ✎ on the chip to edit the code, and click the chip to play! While a program plays it takes over the whole document (text, buttons and songs), and the ■ Stop button at the top-right (or Esc) brings your document back. Bitbook is the editor; the same chip also plays in Omicron.

Your first program

fn onstart():
    renderRT("=Y=Hello=Y= from **BitLang**!", line="1")

fn onstart(): runs once when the program starts. Indentation (4 spaces) shows what belongs to a function, an if or a loop, like in Python.

Variables

var best = 0              # saved between plays (great for high scores!)
var temp score = 0        # temporary: starts fresh every play
score = score + 1
score += 1
var name = "Ava"
var pos = {x: 10, y: 20} # a map
var items = [1, 2, 3]    # a list
  • var keeps its value after you stop, and comes back next time you play.
  • var temp is reset on every play.
  • Values: numbers, "text", true/false, null, lists [ ], maps { }.
  • A bare link is text: var song = https://example.com/#abc
  • Comments start with #.

Functions and events

fn add(a, b=1):
    return a + b

fn onstart():     # once, when the program starts
fn onframe(dt):   # about 60 times a second while it plays; dt = seconds since the last frame
fn onkey(k):      # a key goes down ("a", "arrowleft", "space"...)
fn onkeyup(k):    # a key goes up
fn onend():       # when the program stops

In the code editor, Tab indents to the next step of 4 spaces, Shift+Tab takes one step away, and inside the indentation Backspace, Delete and the arrow keys treat each 4 spaces as one tab.

Call a function with add(2, 3) or by name: add(2, b=5).

onframe only changes the document (renderRT, print, buttons...). Rewriting the same text is free, so a clock or a counter can update every frame:

var temp t = 0

fn onframe(dt):
    t += dt
    renderRT("Seconds: **" + floor(t) + "**", line="1")

Choices and loops

if score > 10:
    print("Great!")
elif score > 5:
    print("Nice")
else:
    print("Keep going")

while lives > 0:
    lives -= 1

for i in range(5):        # 0, 1, 2, 3, 4
    print(i)
for item in items:
    print(item)
# break  continue  pass  return

Operators: + - * / % **, comparisons == != < > <= >=, and or not, and in (3 in items). Text + anything joins: "Score " + score.

Text output

print(a, b, ...)Adds a line of plain text
renderRT(html, line="1")Shows rich text on a numbered line. line="2" takes over line 2, replacing whatever was written there before (by renderRT, a quick command, or print). Leave line out and it adds the next free line instead (the same statement keeps its own line, so a loop or onframe updates it in place). It understands HTML and Keydown: =Y=gel=Y=, **bold**, #C#chip#… Where Poolside Keydown is loaded (Bitbook, Waterflow, Writeout, OpenDB), a part of the text can be written in it with ;;pk{ ... }, like renderRT("Score: ;;pk{ <tip Nice!> }") (use single quotes for any quotes inside).
ink("gel:red:9:M10 10L80 40")Draws on the program's page with Bitbook's Annotate inks, over everything else. The easy way: press ✏️ Draw in the editor, draw, and press Done: the drawing goes into your code as an @@ink="strokes='...'" line, which runs just like ink(...)!
wait(2)Pauses the program for that many seconds (wait(0.5) is half a second), then carries on with the next line! It works on a line of its own: at the top level, in onstart, buttons, keys, and functions of your own called on their own line. A while true: loop with a wait inside never runs out of time, and Stop ends the waiting.
inkc()Clears the ink: every drawing made with ink(...) (or an @@ink line) leaves the page. Draw again any time with ink(...)!
renderPT(text, line="1")Like renderRT, but plain text: no Keydown, no HTML, shown exactly as written (**stars** stay as stars). Same line rules: line=N takes over line N, no line adds the next free line, and inside another call or a & row it just hands back its text.
btn(function, contents)A clickable button! The function runs when it is clicked; the contents can be anything renderRT understands. A button has no style of its own, so whatever you put inside becomes the button: a Keydown chip (#C#Play#), an Annotate highlight, an image, plain text… Show it with renderRT(btn(restart, "↻ Again") + "", line="2"). You can mix buttons, text and skills in one line.

BBML: set up the page without renderRT

BBML is a little markup (it looks like HTML) for a program's starting page. In the ✎ editor, switch the BitLang | BBML button to write it. When the program plays, the BBML lines appear first (right after your top-level code), then onstart runs and keeps adding lines after them.

<!-- comments look like this -->
<line>Welcome, **{name}**! Next year you are {age + 1}.</line>
A loose line of text becomes its own line too.
<row>
    <btn do="start">#G#Start#</btn>
    <btn do="stop">#R#Exit#</btn>
</row>
<line>Name: <textbox var="name">Your name</textbox> Age: <counter var="age" min="0" max="120"/></line>
<line n="9"><annotate type="bubble" color="pink">Line 9, in a bubble</annotate></line>
<pt>Plain text: **these stars stay**</pt>
<line>…</line> <row>One line of rich text (Keydown works). n="9" puts it on line 9. Everything inside, buttons included, sits on that one line.
{expression}Any BitLang expression, worked out when the page is set up: {name}, {age + 1}, {upper(name)}. Write { for a real brace and < for a real <.
<btn do="fn">…</btn>A button that runs a function (or stop, or do="lam(...)"). Its contents are what it looks like.
<textbox var="x">hint</textbox>A textbox tied to a variable (value="..." to start with text).
<counter var="x" min="0" max="9"/>A number box tied to a variable.
<effect saturation="0" blur="1">…</effect>An effect around everything inside (saturation, brightness, contrast, grayscale, sepia, invert, hue, blur, opacity, tint="red" with tintamount="0.5", or filter="a CSS filter").
<annotate type="box" color="3">…</annotate>An Annotate highlight (any type, color by number or name).
<beepbox src="link" label="Song"/>A BeepBox song chip.
<pt>…</pt>Plain text (no Keydown).
<b> <i> <br>…Any other tag is passed through as HTML.

Variables and functions come from your BitLang code, so declare them there (var name = "", fn start():). Mistakes show as BBML line N. In the editor, BBML tag names are bright green, attribute names blue, values and text in quotes green, and {expressions} are colored like BitLang.

Lines: writing and overwriting

fn onstart():
    renderRT("first")                  # no line: takes the next free line (1)
    renderRT("second")                 # line 2
    renderRT("OVERRIDDEN", line=1)     # line 1 now says OVERRIDDEN
    annotate_bubble("quick commands count as lines too")   # line 3
    print("so does print")                                  # line 4

Every piece of output sits on a numbered line, in order. renderRT("text", line=N) always replaces line N, even when it has been written on already, so you can redraw one line (a score, a status) without touching the rest. Without line, a new line is added at the end.

Rows: several things on one line

End a line with & and the next line joins it, so quick commands and buttons sit side by side. They can be stacked as long as you like:

fn onstart():
    btn(submit, renderRT("#C#Submit#")) &
    btn(stop, renderRT("#R#Exit#")) &
    btn(go, renderRT("#G#Go#"))

fn submit():
    renderRT("Submitted!", line=9)

fn go():
    renderRT("Going!", line=9)

The three buttons appear in one row (one output line). & also works inside renderRT(...) to join text pieces, and the next component can be indented however you like. The last line of a row has no &.

onhover: change what shows when the mouse is over it

Give btn, renderRT or renderPT an onhover and its contents are swapped for the new ones while the mouse is over it (it keeps the room for both, so nothing jumps around). The hover contents are Keydown too, like renderRT("**Hi**", onhover="=Y=Bye=Y="), and can be a renderRT(...) result as well. Inside renderPT they stay plain text, no Keydown. The swap fades (add transition=0 to make it instant), and the hover contents can hold effects, like onhover=effect_size("Play", 1.3) to grow while the mouse is over it:

fn onstart():
    renderRT(btn(go, "#C#Play#", onhover="#G#Let's go!#"), line="1")
    renderRT("Move the mouse here", onhover="**Hello!** =Y=Nice to meet you=Y=", line="2")
    renderPT("Plain text", onhover="**stars** stay stars", line="3")
    renderRT(hover(btn(go, "Open"), "Opens the door"), line="4")   # hover(contents, onhover) works on anything

fn go():
    print("clicked")

In BBML, write onhover="..." on <btn>, <pt>, <line>, <row> or <span>, like <btn do="go" onhover="#G#Go!#">#C#Play#</btn>.

Effects: saturation, brightness, blur and more

An effect wraps text with Keydown formatting, or an element like a button or a text box, and changes how it looks. Everything outside it stays as it is:

fn onstart():
    renderRT(effect_saturation("++R+Text++ ", 0) + "Normal text")     # the red chip turns gray
    renderRT(effect_blur("**soft** words", 1.5) + " and sharp ones")
    renderRT(effect_grayscale(btn(go, "#G#Go#"), 1) & btn(go, "#G#Go#"))   # an element: the first button turns gray
    renderRT(effect_brightness(effect_hue("++B+Hue turned++", 120), 1.4))   # effects can sit inside each other

fn go():
    print("clicked")
effect_saturation(x, n)0 is gray, 1 is normal, 2 is extra vivid.
effect_brightness(x, n)0 is black, 1 is normal, 2 is twice as bright.
effect_contrast(x, n)0 is flat gray, 1 is normal, 2 is punchy.
effect_grayscale(x, n) effect_sepia(x, n) effect_invert(x, n)0 is normal, 1 is fully gray, brown or flipped.
effect_hue(x, degrees)Turns every color around the color wheel.
effect_blur(x, pixels)Makes it soft.
effect_opacity(x, n)0 is invisible, 1 is normal.
effect_tint(x, color, n)Colors it, like a colored glass over it: the light and dark parts stay. The color is a name ("red", "slate"), a number 1 to 13 (like annotate), "#336699" or "rgb(51, 102, 153)". n is how strong, from 0 (the original) to 1 (all the way, the default).
effect_size(x, n, seconds)Makes it bigger or smaller: 1 is normal, 1.5 is half as big again, 0.5 is half the size. It grows smoothly and does not push the words around it. Made for onhover, like btn(go, "Play", onhover=effect_size("Play", 1.3)).
effect_shadow(x, dx, dy, blur, color)A soft shadow that follows the shape, like effect_shadow("Hi", 2, 2, 4, "red").
effect(x, "saturate(0.5) blur(1px)")Several at once, written as a CSS filter (blur, brightness, contrast, grayscale, hue-rotate, invert, opacity, saturate, sepia, drop-shadow).

Turning transitions off: add transition=0 (or transition=false, transition="off") to the button, text or effect that you do not want to animate, like btn(go, "Play", onhover=effect_size("Play", 1.3, transition=0), transition=0): the first transition=0 stops the growing, the second stops the fade between the two. Leave it out for the smooth default.

Transitions: every effect eases in over a quarter of a second when it changes (like when the mouse arrives). Add transition=0 (or transition=false) to make it instant, or transition=1 for a slow second: effect_size("Hi", 2, transition=0). effect_size also takes the seconds as its third number. The swap of onhover fades the same way and takes transition= too. Hover contents can hold effects, so a button can grow while the mouse is over it.

The thing inside can be a text, a button (btn), a text box, a skill and so on: write the amount after it. In BBML, <effect saturation="0" blur="1">…</effect> does the same around everything inside it. Numbers outside the sensible range are kept inside it. If a Keydown tag starts before an effect and ends after it, it cannot be drawn: put the whole tag inside the effect.

Lambdas: lam(...)

A lambda is a little function written in one place. Put statements inside lam(...), separated by ;, and keep it in a variable (or hand it straight to a button):

var done = lam(renderRT("Good job! You did it", line=1); btn(stop, renderRT("#R#Exit#")) &; btn(submit, renderRT("#G#Submit#")))

fn onstart():
    done()                  # runs every statement, in order

fn later():
    btn(lam(renderPT("clicked", line=5); beep(660, 80)), "#C#Click me#")   # a lambda as a button's function
  • Each ; starts the next statement, exactly like a new line.
  • A & right before a ; keeps the next statement on the same line of output (the & row rule), so the Exit and Submit buttons sit side by side.
  • A lambda takes no values. It sees your variables, and return works inside it.

Saving data (browser storage)

ls_set(key, value)Saves a number, text, true/false, list or map under a name. It is still there next time (even after closing the page).
ls_get(key, default)Reads it back (or default, or null, when nothing is saved).
ls_remove(key)Forgets one key.
ls_keys()A list of every key this program saved.
ls_clear()Forgets all of this program's keys.
to_json(x) from_json(text, default)Turn a list/map into text and back (handy with files).
var temp visits = ls_get("visits", 0)
fn onstart():
    ls_set("visits", visits + 1)
    renderPT("You have been here " + (visits + 1) + " times", line=1)

Every program has its own private shelf. Add shared=true (like ls_get("name", "", shared=true)) to use a shelf all programs share. (var variables are also saved for you, but ls_ gives you named keys, lists and maps.)

Files: export_file and import_file

export_file(name, text)Saves a text file to the person's computer (their browser downloads it).
import_file(fn)Opens the file picker. When a file is chosen, fn(name, text) runs with its name and text. Add accept=".csv,.json" to limit the types. Files up to 1 MB.
fn onstart():
    btn(pick, "#C#Open a file#") &
    btn(save, "#G#Save a file#")

fn pick():
    import_file(got)

fn got(name, text):
    renderPT(name + " has " + len(text) + " letters", line=3)

fn save():
    export_file("hello.txt", "Hello from BitLang!")

The browser only opens the picker (or a download) after a click, so call these from a button's function. Programs can only read a file the person picks, and only save through a normal download.

Regex (patterns for text)

regex_test(pattern, text)true if the pattern is found anywhere in the text.
regex_match(pattern, text)The first match as a map (m.text, m.index, m.groups = the (...) parts, m.named for (?<name>...) parts) or null.
regex_all(pattern, text)A list of every match (add full=true for maps like regex_match).
regex_replace(pattern, text, with)Replaces every match. $1 in with is the first (...) part.
regex_split(pattern, text)Cuts the text at each match into a list.
regex_test("^[A-Z]", "Hello")                       # true
regex_all("\d+", "a1 b22 c333")                      # ["1", "22", "333"]
regex_replace("(\w+)@(\w+)", "me@site", "$2/$1")    # "site/me"
regex_match("(?<y>\d{4})-(\d\d)", "on 2026-10").named.y   # "2026"

Patterns work like JavaScript's. Write a backslash twice inside quotes ("\d" for a digit). Add flags="i" to ignore case (also m, s). Patterns up to 500 letters and texts up to 200,000 letters; a bad pattern shows a plain error.

Buttons (step by step)

A button runs one of your functions when someone clicks it. You need two things: a function that says what happens, and a btn(...) that puts a clickable thing on the page.

1. The smallest button

fn onstart():
    btn(hello, "Click me")

fn hello():
    renderRT("You clicked it! =Y=Hooray=Y=", line="2")
  • btn(hello, "Click me") has two parts: first the function's name, then what the button looks like.
  • Write the function name without brackets: hello, not hello(). With brackets you would run it right now instead of giving it to the button.
  • On a line of its own, btn(...) shows itself. Inside other text, use renderRT (see 3).

2. A button that changes something (a counter)

var temp clicks = 0

fn onstart():
    draw()

fn draw():
    renderRT("Clicks: **" + clicks + "** " + btn(add, "#C#+1#"), line="1")

fn add():
    clicks += 1
    draw()
  • A button's function takes no values, so keep what you need in a var or var temp (here clicks).
  • Pressing the button changes clicks, then draw() writes the same line again with the new number. Writing a line again replaces it, so the button stays in place.

3. Buttons inside text, and several at once

fn onstart():
    renderRT("Pick one: " + btn(red, "Red") + " " + btn(blue, "Blue"), line="1")

fn red():
    renderRT("You picked **red**!", line="2")

fn blue():
    renderRT("You picked **blue**!", line="2")

Join buttons with + and text, like any other text. Each btn needs its own function.

4. Make the button look like anything

A button has no style of its own: whatever you put inside becomes the button. Try a Keydown chip, an Annotate highlight (the quick commands are perfect), or an image:

fn onstart():
    renderRT(btn(go, "#C#Go!#") + " " + btn(go, annotate_bubble("Or this", color=6)) + " " + btn(go, annotate_accent("Or this", 10)), line="1")

fn go():
    renderRT("Went!", line="2")

5. A button that stops the program

fn onstart():
    btn(stop, "Quit")

Built-in commands like stop work as the function too. (The ■ Stop button, or Esc, always works as well.)

If your button does nothing

  • Did you write btn(hello, ...) and not btn(hello(), ...)?
  • Is there a fn hello(): in your code with the same spelling?
  • Is it on a line of its own, or inside renderRT(...)? A button saved in a variable is not shown until you give it to renderRT.
  • Did the program stop before you clicked? A program with only onstart keeps running until you press ■ Stop, but an error stops everything: read the red message!
  • Buttons cannot hand values to the function (btn(add(5), ...) will not work). Put the value in a var first.

Typing: textbox() and counter()

While a program plays, the page can't be edited, so nobody can change your text by accident. The exceptions are boxes you add yourself:

var name = ""
var temp age = 0

fn onstart():
    renderRT("Name: " + textbox("Type your name", variable=name), line="1")
    renderRT("Age: " + counter(variable=age, min=0, max=120), line="2")
    renderRT(btn(hello, "#C#Say hi#"), line="3")

fn hello():
    renderRT("Hi **" + name + "**, you are " + age + "!", line="4")
textbox(placeholder, variable=x)A box to type in. variable=x (no quotes) updates the variable while the person types. The short form textbox("Text here", x) does the same. The placeholder is the dimmed hint; it understands Keydown and skills (textbox(annotate_box("Name")), even songs). value="..." sets what it starts with.
counter(variable=x, min=0, max=10)(Short form: counter(x).) A smaller box for numbers only (digits, one dot, a leading minus). The variable gets a real number. Empty counts as 0. min and max are applied when the person leaves the box. It takes a placeholder too, but no Keydown typing.
  • People can type Keydown into a textbox (**bold**, =Y=gel=Y=), but the variable gets its plain text ("bold", "gel"). They cannot add skills: anything typed is only text.
  • A variable only changes when the text really changed, so typing stays smooth.
  • If your program changes the variable (name = ""), the box shows the new value. Create the variable with var or var temp before using it in variable=....
  • Like buttons, boxes need renderRT (or a line of their own) to appear. Keys typed inside a box don't trigger onkey.

Skills inside programs

var temp song = https://ultraabox.github.io/#u5N0btuff...

fn onstart():
    renderRT(skill(skill="beepbox", get=song, content=inherit) + "", line="1")

skill(skill="beepbox", get=link, content=inherit) builds a BeepBox song player. content=inherit means the song data is taken from the link itself (inherit only works with the BeepBox skill). Add label="My song" to name the chip. In Bitbook the chip plays the song; in Omicron it opens the link.

Annotate: highlights in your text

renderRT("Look: " + skill(skill="annotate", type="bubble", color="pink", content=renderRT("Some **totally random** text here")), line="1")

skill(skill="annotate", type=..., color=..., content=...) wraps text in one of Bitbook's Annotate highlights. content can be renderRT("..."): used inside another call, renderRT just hands back its rich text instead of showing it. type is highlight, underline, strikethrough, box, halo, brackets, spotlight, accent, bubble or one of the colorful ones: dusk prism complement ticket neon stamp tape checker halftone aurora mild (pale versions of every color) wrap belt bucket torpedo bottle packet select capsule frost pixel flag gem. color (default yellow) is red, orange, gold, yellow, lime, green, turquoise, teal, cyan, blue, purple, pink or slate. Annotate highlights make great btn contents!

Matchers: find and swap

var who = "Text"

mat Censor: (
    "badword"        ~> "*******"
    "just some text" ~> 1
)

mat Swap: (
    "matchme"    ~> "replaceme"
    "a_variable" ~> who          # a value can be a variable
    who          ~> "a_variable" # and so can what you look for
)

fn onstart():
    renderRT(mat_match("a_variable", Swap), line=1)          # Text
    renderRT(mat_match("no badword here", Censor), line=2)   # no ******* here
    renderPT(mat_match("just some text", Censor), line=3)    # 1
  • mat Name: ( ... ) makes a matcher: one "what to find" ~> what it becomes per line (commas are fine too, and # comments work inside).
  • mat_match(x, Name): if x is exactly one of the keys, you get its value (any kind: text, a number, a list...). Otherwise, if x is text, every key found inside it is swapped (longest first).
  • Swapping happens once: a replacement is never matched again, so "a_variable" becomes "Text" and stays "Text" even though "Text" is also a key.
  • Keys and values are read when you match, so they always use the variables' current values.
  • mat_match(list, Name) matches every item. mat_has(x, Name) is true when anything matched, and mat_keys(Name) lists the keys.
  • Change a pair with matc and the mouse operator ">: matc Censor ["badword" ~> "*******"] "> ["badword" ~> "(oops)"]. The first [...] is the pair as it is now (key and value), the second is what it becomes. The new key and value are read right then.
  • Not to be confused with mat(...), which makes a matrix: a matcher is mat, a name, then a colon.

Vectors and matrices

var v = <| 1, 2, 3 |>        # a vector: <| numbers, separated by commas |>
var m = [1 2; 3 4]            # a matrix: numbers with spaces, ; starts a new row
var id = identity(2)          # [1 0; 0 1]
  • Vector <| 1, 2, 3 |> (or vec(1, 2, 3)). Read parts with v[0] or v.x v.y v.z v.w, count with v.length or len(v), change with v[1] = 9 or v[1] += 5, and loop with for x in v:.
  • Matrix [1 2; 3 4] (or mat([[1, 2], [3, 4]])). Spaces separate the numbers, so use brackets for sums: [(1 + 2) 4], and [1 -2] is two numbers. m[1] is a row (a live vector), m[1][0] one number, m.rows m.cols and m.T (the transpose) work. [1, 2; 3, 4] with commas is fine too, and then each part can be a full sum.
  • Plain [1, 2, 3] with commas and no ; is still a normal list.
v + w v - wAdd or subtract vectors (or matrices) of the same size.
v * 2 2 * v v / 2Scale. A number with + or - goes into every slot.
v * wVectors multiply slot by slot. For the dot product use dot(v, w).
m * n m * v m ** 3Matrix times matrix, matrix times vector (the vector stands up as a column), and matrix power.
dot(v, w) cross(v, w) norm(v) normalize(v)Dot product, cross product (3 numbers each), length, and the same direction with length 1.
det(m) inverse(m) transpose(m) trace(m)Determinant, inverse, transpose, and the sum of the diagonal.
identity(n) zeros(n) zeros(r, c)The identity matrix, a vector of zeros, and a matrix of zeros.
rows(m) cols(m) to_list(x)Sizes, and turn a vector or matrix into plain lists.
v == wAre they the same numbers? (Vectors and matrices cannot be compared with < or >.)
var temp m = [2 0; 0 2]
fn onstart():
    renderPT("m * <| 1, 3 |> = " + str(m * <| 1, 3 |>), line=1)     # <| 2, 6 |>

They show up as <| 1, 2, 3 |> and [1 2; 3 4] in text. Saved vars and ls_set keep them. A matrix only holds numbers. A vector can hold numbers, text, true/false and variables, like a list that also does vector math: <| name, "hi", 3, ok |> (the variables name and ok are read when the vector is made). + * still work slot by slot on text (+ joins, * 3 repeats); the number-only tools (dot, cross, norm, normalize, matrix products) ask for numbers.

Libraries: use python, use sqlite, use lua

Put use lines at the very top of your program to load a library. They load before the program starts (you will see a loading message the first time).

use sqlite
use python
use python numpy, pandas      # extra Python packages from Pyodide's list
use lua

python(code) (Pyodide)

use python

fn onstart():
    var temp total = python("sum(range(10)) * k", k=2)     # 90
    renderPT("total = " + total, line=1)
    python("import math\nroots = [math.sqrt(x) for x in range(4)]")
    renderPT(to_json(python("roots")), line=2)             # variables stay for the next python() call
    python("print('hello from Python')")                   # prints show up as lines
  • python("code") runs the code and gives back the value of its last expression (numbers, text, true/false, None = null, lists, and dicts become maps). Extra name=value pieces become Python variables first (k=2 above).
  • Python keeps its variables between calls while the program runs. Errors show the Python message and the line of your BitLang program.
  • The first run downloads Pyodide (about 10 MB) from the internet; after that it is cached by the browser.
  • Python is more powerful than BitLang, so the first time you play a program that uses it you are asked to Allow it (you can tick "Always allow this exact program"). BitLang blocks Python's js module (the way into the page), but treat this as a safety net, not a wall: only allow programs you trust.

sql(query, params) (SQLite)

use sqlite

fn onstart():
    sql("create table scores (name text, points integer)")
    sql("insert into scores values (?, ?)", ["Ann", 12])
    sql("insert into scores values ('Bob', 7)")
    var temp rows = sql("select * from scores order by points desc")
    renderPT(rows[0].name + " leads with " + rows[0].points, line=1)
    sql_save()          # keeps the database in this browser; sql_load() brings it back later
  • sql(query) gives a list of maps for a SELECT (one map per row, columns as names) and the number of changed rows for anything else. Put ? in the query and a list as the second value to fill them safely.
  • The database starts empty each time the program plays (it lives in memory). sql_save() stores it (up to 3 MB) and sql_load() returns true when it found a saved one. Use name="other" for more than one.
  • SQLite runs in a sealed box (sql.js), so it needs no permission.

lua(code) (Fengari)

use lua

fn onstart():
    renderPT("sum = " + lua("local t = 0 for i = 1, n do t = t + i end return t", n=5), line=1)   # 15
    renderPT(lua("string.upper('hi')"), line=2)        # a single expression gives its value back
    lua("print('Hello from Lua!')")                     # prints show up as lines
  • lua("code") runs Lua 5.3 (Fengari, a Lua written in JavaScript). Use return to give a value back, or pass just an expression. Tables like {1, 2, 3} become lists and {name = "Ann"} becomes a map; nil is null.
  • name=value pieces become Lua variables first, and Lua's own variables stay between calls while the program runs.
  • Lua runs in a sealed box: no files, no require, and no way into the page or JavaScript, so it needs no permission. An endless loop is stopped for you.
  • Strings in Lua can use single quotes, which is handy inside BitLang's double quotes: lua("print('hi')").

If something goes wrong

BitLang shows the line number and a plain-English message in the document. An endless loop is stopped for you after a moment. Programs can't touch the rest of your note or your files: they only change the document you are playing in.
